## 2. 全局前端约定

### 2.1 请求入口

前端请求统一使用公共 Axios 实例，不在业务页面中直接调用原生 `axios` 或 `fetch`。

请求通过 `/api` 进入网关，由网关转发到对应微服务。

主要服务前缀包括：

| 服务    | 前端请求前缀                |
| ----- | --------------------- |
| 认证服务  | `/edu-agent-auth`     |
| 学习服务  | `/edu-agent-learning` |
| 资源服务  | `/edu-agent-resource` |
| 教师服务  | `/edu-agent-teacher`  |
| AI 服务 | `/edu-agent-ai`       |
| 代码服务  | 按当前代码服务接口配置           |
| 管理员服务 | 等待正式接口进一步确认           |

### 2.2 Token 与异常处理

公共请求层已实现：

* 自动读取并携带登录 Token
* 使用 Bearer Token 认证方式
* 统一解包后端通用响应结构
* 兼容普通结果与分页结果
* 统一处理登录状态失效
* 401 响应时清理本地认证状态并跳转登录页
* 业务失败时返回错误信息，不使用本地假数据伪装请求成功

### 2.3 权限与路由

前端按角色区分：

* `ROLE_STUDENT`
* `ROLE_TEACHER`
* `ROLE_ADMIN`

路由守卫根据登录状态及用户角色限制页面访问。不同角色不能直接进入其他角色的业务页面，登录成功后根据角色进入对应首页。

## 4. 认证模块

### 4.1 已处理功能

* 用户登录
* 用户注册
* 获取当前用户信息
* 刷新认证信息
* 本地退出登录
* 登录用户信息及角色保存
* 不同角色登录后的页面跳转

### 4.2 接口契约处理

注册请求支持：

* `username`
* `password`
* `realName`
* `email`
* `phone`
* `role`

刷新认证信息时提交 Token，并按照登录结果结构接收刷新后的认证信息。

当前用户信息模型支持：

* 用户编号
* 用户名
* 真实姓名
* 角色列表
* 用户状态
* 邮箱
* 手机号
* 引导完成状态等前端已有字段

由于当前已确认的认证服务没有提供服务端退出端点，前端不发送不存在的退出请求。退出操作负责清理本地 Token、角色及用户信息，并跳转至登录页。

### 4.3 待确认内容

* Onboard 完成状态接口
* 正式刷新 Token 策略
* 用户状态和引导状态的最终字段定义

## 6. AI 助教聊天模块

### 6.1 请求结构

AI 助教聊天请求使用：

```json
{
  "user_input": "用户输入内容",
  "student_id": "当前登录学生编号",
  "session_id": "当前会话编号",
  "profile": {}
}
```

`student_id` 从当前登录用户状态中获取，不使用固定测试编号。

### 6.2 响应结构

前端当前支持读取：

* `intent`
* `final_answer`
* `profile`
* `resources`
* `learning_path`
* `safety_report`
* `evaluation_report`
* `resource_dir`
* `profile_complete`

聊天页面使用 `final_answer` 展示 AI 回复，并保留结构化消息展示能力。

### 6.3 当前边界

本次仅对齐已经确认的 AI 聊天链路，不将以下尚未完整确认的功能视为最终完成：

* AI 画像构建
* AI 画像查询
* AI 题目讲解
* AI 学习路径生成
* AI 教学资源生成的全部调用链
* Onboard 对话与完成状态联动

这些功能需要取得正式接口文件或完成联调后继续调整。
